# نسخه‌ی اندروید (Capacitor)

## وضعیت فعلی

پلتفرم اندروید کامل اضافه و پیکربندی شده (`android/` — پروژه‌ی واقعی Android Studio/Gradle) و
`npx cap doctor` آن را تایید کرد. مجوزهای دوربین، GPS، میکروفون، و اعلان به `AndroidManifest.xml`
اضافه شدند — چون این اپ به‌شدت به این‌ها وابسته است (دوربین زنده با واترمارک، GPS پیش‌گرم‌سازی
مشترک، یادداشت صوتی حادثه). `MainActivity` از `BridgeActivity` استاندارد Capacitor استفاده می‌کند
که خودش درخواست این مجوزها از WebView (دوربین/میکروفون/GPS) را مدیریت می‌کند — نیازی به کد بومی
اضافه نبود.

**صادقانه: نتوانستم واقعاً یک APK بسازم.** محیطی که این پروژه در آن نوشته شده، اگرچه Java 21 دارد،
اما به `services.gradle.org` (برای دانلود خود Gradle) و به سرورهای Google (برای Android SDK)
دسترسی شبکه ندارد — یعنی مرحله‌ی نهایی کامپایل باید روی دستگاه خودتان (که به اینترنت کامل دسترسی
دارد) انجام شود.

## ساخت APK — مرحله‌به‌مرحله

### پیش‌نیاز
[Android Studio](https://developer.android.com/studio) را نصب کنید (خودش JDK و Android SDK لازم
را همراه دارد، نیازی به نصب جدا نیست).

### مراحل

```bash
# اولین بار بعد از اضافه‌شدن هر وابستگی جدید (مثل background-geolocation)، این را هم بزنید
npm install

# هر بار که کد وب عوض شد، این را بزنید تا آخرین build داخل پروژه‌ی اندروید کپی شود
npm run cap:sync

# پروژه را در Android Studio باز کنید
npm run cap:open
```

داخل Android Studio:
1. صبر کنید Gradle Sync اولیه تمام شود (چند دقیقه، چون باید Android SDK/Gradle را دانلود کند)
2. از منو: **Build → Generate Signed Bundle / APK** (برای انتشار در Google Play یا نصب مستقیم)
   یا برای یک تست سریع: **Run ▶** با یک شبیه‌ساز/گوشی متصل
3. برای انتشار در Google Play، به یک keystore امضا نیاز دارید — راهنمای رسمی:
   https://developer.android.com/studio/publish/app-signing

## نکات مهمی که باید روی دستگاه واقعی تست کنید (نه فقط شبیه‌ساز)

- **دوربین زنده با واترمارک** (`getUserMedia`) — باید داخل WebView هم کار کند، ولی رفتار
  دقیق روی برندهای مختلف گوشی می‌تواند فرق کند.
- **بیومتریک** (`navigator.credentials` / WebAuthn) — پشتیبانی WebAuthn داخل Android WebView
  نسبتاً جدید و گاهی ناپایدار است؛ اگر کار نکرد، دکمه‌ی «فعال‌سازی» را نشان نمی‌دهد (چون
  `bioSupported()` چک می‌کند)، پس حداقل خرابی بی‌صدا نخواهد بود — ولی حتماً تست کنید.
- **اعلان‌های محلی** (`Notification` + service worker) — WebView از service worker پشتیبانی
  می‌کند، ولی رفتار اعلان داخل یک اپ بسته‌بندی‌شده (نه یک PWA نصب‌شده‌ی مستقل) می‌تواند کمی
  متفاوت باشد.
- **صف آفلاین (IndexedDB)** — باید بدون مشکل کار کند (IndexedDB استاندارد و پشتیبانی‌شده در
  WebView است)، ولی حتماً یک بار قطع/وصل اینترنت واقعی را تست کنید.

اگر هرکدام از این‌ها روی دستگاه واقعی مشکلی داشت، جزئیات خطا را برایم بفرستید تا رفعش کنم —
اکثر این مشکلات (اگر پیش بیایند) با تنظیمات جزئی در `AndroidManifest.xml` یا `capacitor.config.ts`
قابل‌حل‌اند، نه بازنویسی.

## ردیابی پس‌زمینه‌ی ورود/خروج از معدن (`@capacitor-community/background-geolocation`)

این وابستگی برای این اضافه شده که ورود/خروج مسئول فنی/ایمنی/بهداشت از محدوده‌ی معدن حتی وقتی
اپ کامل بسته (از لیست اپ‌های اخیر پاک) شده هم ثبت شود — کد سمت وب در `src/lib/backgroundGeofence.js`
و `src/lib/mineGeofence.js` است. **این بخش هرگز روی گوشی واقعی اجرا/تست نشده** (نه امکان build
اندروید در محیطی که این کد نوشته شده بود، نه امکان اتصال دستگاه واقعی) — قبل از انتشار عمومی حتماً
موارد زیر را تست کنید:

- **تست اصلی:** با نقش مسئول فنی وارد شوید، اپ را کامل ببندید (از لیست اپ‌های اخیر پاک کنید)، به
  محدوده‌ی یکی از معدن‌های اختصاصی وارد/خارج شوید، و مطمئن شوید در تب «ساعات حضور در معدن» پنل
  ادمین رویداد ثبت شده.
- **نوتیفیکیشن دائمی:** باید بلافاصله بعد از ورود به این اپ (اگر مسئول فنی/ایمنی/بهداشت باشید) یک
  نوتیفیکیشن ثابت با عنوان «ثبت حضور در محدوده معدن» ظاهر شود که تا وقتی خارج نشده‌اید باقی می‌ماند
  — این طبیعی و اجباری اندروید است (سرویس foreground بدون نوتیفیکیشن قابل‌اجرا نیست)، نه یک باگ.
- **گوشی‌های چینی با مدیریت باتری تهاجمی (شیائومی/MIUI، هواوی، اوپو و...):** این برندها معروفند
  به این‌که سرویس‌های foreground را هم گاهی می‌کشند مگر کاربر دستی «بدون محدودیت باتری» را برای
  این اپ فعال کند. اگر چند نفر از مسئولین فنی همچین گوشی‌هایی دارند، باید از آن‌ها بخواهید این
  تنظیم را دستی فعال کنند (معمولاً: تنظیمات ← باتری ← این اپ ← بدون محدودیت).
- **سازگاری نسخه‌ی Capacitor:** این پلاگین رسماً تا Capacitor v7 تست/پشتیبانی شده؛ این پروژه روی
  Capacitor 8 است. اگر بعد از `npm install` و `npx cap sync android` خطای build دیدید، به
  Issues مخزن پلاگین (`capacitor-community/background-geolocation`) برای سازگاری با v8 سر بزنید.
- **مجوز موقعیت مکانی:** این پلاگین از راه سرویس foreground استفاده می‌کند، نه مجوز جداگانه‌ی
  «دسترسی همیشگی به موقعیت مکانی» (`ACCESS_BACKGROUND_LOCATION`) — یعنی نیازی به فرم/بازبینی
  سخت‌گیرانه‌ی گوگل‌پلی مخصوص آن مجوز نیست. با این حال، موقع آپلود روی Google Play Console، در
  بخش «App content → Permissions declaration»، حضور یک foreground service از نوع location را
  ممکن است لازم باشد توضیح دهید (چرا لازم است: «ثبت خودکار ساعات حضور مسئولین فنی در محدوده‌ی
  معدن برای گزارش‌گیری اداری»).
- محدودیت شناخته‌شده: بعد از ۵ دقیقه در پس‌زمینه، ارسال HTTP از WebView (fetch معمولی) کند/محدود
  می‌شود — یعنی ممکن است اعلان فوری به ادمین (نه خودِ ثبت رویداد، که در صف آفلاین امن است) چند
  دقیقه دیر برسد.
